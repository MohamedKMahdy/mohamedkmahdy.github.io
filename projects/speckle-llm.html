Speckle · local LLM

ARVENT

I put an LLM on BIM data before it was a category.

  • Python
  • FastAPI
  • Speckle (GraphQL, webhooks, specklepy)
  • Ollama
  • Llama 3.1
  • SQLite

The problem

Most people on a project never open the model, but they still have questions about it: what this panel's U-value is, how many doors lack a fire rating, whether the latest version still meets the spec.

What it does

In 2023 I connected Speckle to a large language model so project teams could ask questions about a 3D model in plain language. ARVENT (Assistant for Requirements, Verification and Element Notes in Threads) is the 2026 rebuild. It runs on a local Llama through Ollama, so model data and project documents never leave the machine.

It works inside Speckle comment threads. It answers questions about a selected element from its parameters and any attached specification PDF, with page citations. It answers questions about the whole model. And it checks every new model version against rules drawn from the specification, opening one thread per failing rule that isolates the offending elements in the viewer and replying when a later version fixes them.

The language model never computes and never writes SQL. It fills a JSON query plan constrained to the index's real field names; code validates and repairs the plan and runs it as parameterised SQL, and every reply shows the exact query and result. Rules from the specification are proposed by the model and only run once a person approves them.

Along the way I also built a custom Speckle-Revit connector for a separate client, extending open interoperability between the two platforms.

Features

  • Answers questions about a selected element from its parameters and any attached specification PDF, with page citations
  • Answers questions about the whole model, such as counts, totals and breakdowns per level
  • Every element of the latest version of each model sits in a local SQLite index
  • The Llama only fills a JSON query plan; code checks and repairs it and runs it as parameterised SQL
  • Each reply shows the exact query and result, plus a link that opens exactly those elements in the Speckle viewer
  • Proposes rules from specification PDFs; a person approves them before they run
  • Checks every new model version and opens one pinned thread per failing rule, isolating the elements in the viewer
  • Replies "Resolved" when a later version fixes the problem
  • Missing values are stated, never invented, and citations are checked against the supplied documents
  • Runs on a local Llama through Ollama, so model data and documents never leave the machine
  • Works with both Speckle data shapes (v2 Revit parameters and v3 properties)
  • Webhook server with signature check and de-duplicated retries; command line for indexing, questions and checks; Docker setup with GPU
HighlightThe lesson from 2023 still holds: the model was never the hard part. The hard part is getting clean, queryable, structured data out of the authoring tools.
